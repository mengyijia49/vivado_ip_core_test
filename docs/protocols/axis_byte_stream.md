# AXI-Stream 字节级检查

位宽转换会改变输出拍数，不能拿输入的一拍直接比较输出的一拍。
当前字节后端把收发数据拆成有序条目：数据字节、位置字节，以及包尾。
同一拍从低字节开始，每个字节带上对应的 TUSER、TID、TDEST。

## 比较规则

- 数据字节检查数值；位置字节只检查位置和侧带，不比较没有定义的数据值。
- 空字节可以被删除或补入，不计入期望条目。
- TLAST 单独形成包尾条目，纯空字节组成的空包也不能丢。
- 显式 TKEEP=0、TSTRB=1 属于保留组合，报错，不按空字节放过。
- 输出握手前，对应输入必须已经握手。暂停时 TVALID 和有效内容必须保持。

依据是 [Arm AXI-Stream IHI 0051B](https://documentation-service.arm.com/static/64819f1516f0f201aa6b963c)
的字节限定、宽度转换、包边界和握手规则。检查不假定 IP 内部用了哪种打包算法。
未知值只允许出现在无定义的数据或空字节侧带中，不能屏蔽有效结果的差异。

## 双重检查与记录

VHDL 在每次输出握手后比较条目，同时保存未经拆分的原始输出。
Python 再独立解析原始输出、按同样的协议规则比较期望值。
缺少原始输出文件也算失败，不能只复制一个看似正确的结果文件就通过。
期望条目逐条生成和写入文件；内存中仍保留输入与条目对应表，但不同时保存所有条目字典。

除[公共流接口文件](axis_stream.md)外，每次运行还保存：

| 文件 | 内容 |
| --- | --- |
| `vectors/expected_output.txt` | 字节和包尾条目，不是总线原始拍 |
| `vectors/expected_mask.txt` | 每个条目的有效比较位 |
| `vectors/required_inputs.txt` | 每个条目对应的最少已接收输入数 |
| `outputs/actual_output.txt` | VHDL 拆出的条目 |
| `outputs/accepted_output.txt` | DUT 实际握手的原始总线拍 |
| `outputs/protocol_summary.txt` | 收发拍数、检查条目数和暂停次数 |

`input_transfer_count` 是发出的输入拍数，`reference_token_count` 是要比较的条目数。
`generated_count`、`unique_count` 仍指输入策略选出的数值样本，不包含定向协议前缀，
也不是字节数或协议状态覆盖率。三种数量不能混在一起比较。

## 范围

目前只有位宽转换器使用这个后端；透明流 IP 仍使用原样事务比较。
初始复位、连续传输、输入间隔和输出回压已接入，运行中复位尚未接入。
不测试模拟亚稳态，不做协议认证，也不做综合后仿真。
