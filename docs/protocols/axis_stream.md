# AXI-Stream 自检

当前共用这个后端的是寄存器片、数据 FIFO 和时钟转换器。它们不改变有效数据，
Python 参考结果就是输入事务的原样副本，不是算术模型。
子集转换器也共用按拍检查，但输入和输出可有不同字段和位宽，使用自己的映射参考模型。
位宽转换器沿用握手驱动，但改用[字节级比较](axis_byte_stream.md)，不要求收发拍数相等。
[广播器](../ip/axis_broadcaster/selfcheck.md)共用生成和归档入口，但使用独立多支路检查模板，
允许支路先后握手，不能套用单输出的“接收数不超过上游握手数”检查。
[汇合器](../ip/axis_combiner/selfcheck.md)使用多输入模板，独立安排各路间隔，检查拼接和主接口选择。
其各路输入按组配对，包尾分别安排，不能套用单输入后端的统一包长。
[交换器](../ip/axis_switch/selfcheck.md)不按组等待其他输入，分别维护来源到输出的队列。
带缓冲的不同输出可以先后完成，不能套用全局固定顺序。
全部使用行为仿真，没有综合、网表或时序仿真。

## 怎么检查

1. 生成 TDATA，以及启用的 TID、TDEST、TUSER 边界值和随机值。
2. 安排包长、源端间隔和接收端回压。输入值、顺序、间隔、回压各用独立随机流。
3. 源端发出 TVALID 后保持数据，直到 TVALID、TREADY 同时为 1 才记作接收。
4. 输出也只在握手时比较。逐笔核对数据、侧带和顺序，并检查不能凭空出现输出。
5. 输出暂停时检查 TVALID 和数据保持，结束后再观察 64 个输出时钟，检查多余输出。
6. Python 复核输出文件和实际接收的输入文件。没有收齐时由 watchdog 报错，不会空跑通过。

输出延迟不固定，尤其异步转换不能用固定周期采样代替握手检查。
依据见 [PG085 延迟说明](https://docs.amd.com/r/en-US/pg085-axi4stream-infrastructure/Performance)。

初始复位保持 200 ns。同步接口时钟周期为 10 ns，异步接口分别为 10 ns、14 ns。
接收端先长时间暂停，再循环使用含长暂停、连续接收和随机位的 ready 序列。
这会给缓冲区施加压力，但不根据输入预算推定它一定到过满状态。

## 留下什么

- `vectors/input_vectors.txt`、`expected_output.txt`：计划输入和期望输出。
- `vectors/gaps.txt`、`ready.txt`、`schedule.json`：确定性的输入间隔和回压安排。
- `outputs/accepted_input.txt`、`actual_output.txt`：实际握手的输入和输出。
- `outputs/protocol_events.txt`：输出周期号、valid/ready 和原始数据，出错前也会刷新到文件。
- `outputs/protocol_summary.txt`：收发笔数、源端和输出端暂停周期数。

以上文件位于本批日期目录，并随关键文件归档。

## 还没覆盖

KEEP、STRB 当前只发送全 1，不测试空字节和部分有效字节。
TLAST 安排了短包、缓冲深度附近和超过深度的包；预算不足时不保证每种包长都出现。
当前不检查包模式的最早释放时刻，不测试运行中复位、单侧复位、时钟停止或模拟亚稳态。
没有做完整 AXI 协议认证，也不把输入覆盖率当成状态和时序覆盖率。
这些限制必须随报告解释，不能仅凭 PASS 宣称协议全部正确。
