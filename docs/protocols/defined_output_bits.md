# 有效位比较

没有有效数据时，或手册明确说明结果不确定时，不应拿输出和一个固定数字比较。
目前只有块存储器和原生 FIFO 显式启用逐位掩码，原有算术和 AXI-Stream 检查保持严格。

## 文件含义

- `expected_output.txt` 保存期望值；不确定的位使用占位值。
- `expected_mask.txt` 与它逐行、逐位对应：1 表示必须比较，0 表示该位不确定。
- `cycles.json` 保存不确定范围及原因，不根据 DUT 的实际值选择掩码。
- `actual_output.txt` 始终保存未经掩码处理的原始输出，包括 X、U 等未知值。

Testbench 比较有效位，Python 仿真后再按同一掩码复核。
有效位上的数值差异或未知值仍然失败。声明的掩码缺失、长度不符、含非法字符，
以及整个实验没有任何有效位，都不能判 PASS。
生成器还要求每个输出端口至少有一次有效位检查。
掩码文件与输入、期望值一起计算哈希并归档，不是可随意追加的错误忽略清单。

## 排查失败

先看 `failure_evidence` 的输出行号、期望值、原始实际值和 expected_mask。
逐周期 IP 同时保存该采样周期及之前 8 个周期；它们帮助排查，但不保证包含最早原因。
双端口写冲突产生的不确定位会留在参考存储内容中，直到一次确定写入覆盖它。
报告会记录各端口有效比较位数和各类屏蔽原因，方便检查是否大部分测试都失去了判断依据。

框架的人工故障测试确认：未定义位的 X 可保留，有效位翻转或变为 X 会失败。
这些是检查器测试，不是已发现的 AMD IP bug。
