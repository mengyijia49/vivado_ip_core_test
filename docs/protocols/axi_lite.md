# AXI-Lite 自检

公共实现位于 `plugins/common/axilite/`，仍由外层唯一的 TestbenchGenerator 调用。
目前供 AXI GPIO 和 AXI Timer 使用，只做行为仿真。

## 怎么驱动

写地址、写数据的 VALID 同时发出，分别等待各自握手；先完成的一路单独撤销 VALID。
这遵守 GPIO 和 Timer 的接口限制，也允许两个 READY 不在同周期出现。
读地址握手后等待读响应。一次只保留一个未完成请求，不混发读写。

BREADY、RREADY 在响应 VALID 出现后再延迟 0、1、2、7、16、32 个周期等长度。
这样回压确实落在响应上，而不是恰好错开。操作间隔由种子和配置决定。
每次请求或响应最多等待 512 个周期，另有总看门狗。

检查器核对请求先于响应、响应数量、响应码、未知有效信号和 READY，
以及回压期间 VALID、响应码、读数据保持不变。最后留 64 个空闲周期检查多余响应。
总线输入从实际握手采样并与计划输入比较，避免只验证“原本想发送”的数据。
响应必须对应更早时钟沿已经接收的请求，不能抢在请求握手的同一个沿出现。
依据 [AMD 协议检查说明](https://docs.amd.com/r/en-US/pg101-axi-protocol-checker/AXI-Protocol-Checks-and-Descriptions)
中的写响应依赖与读地址先后规则。

## 怎么比较

IP 插件按操作顺序计算寄存器和引脚状态，输出期望值及明确的有效位掩码。
VHDL 在操作完成后比较；仿真通过后，Python 再复核实际输入和输出文件。
两次比较共用参考文件，不是两个独立参考模型。

数值差异全部保存在 `outputs/mismatches.txt`，仿真在整段序列结束时报告失败。
协议违规立即失败。`outputs/axi_events.txt` 逐周期记录五个总线通道的握手和数据。
`vectors/vectors.json` 保存操作历史，`schedule.json` 保存间隔和响应回压长度。

目前仅在事务之间复位，没有在未完成请求中复位，也未检查并行未完成事务。
GPIO 在每次操作后等待 64 周期再比较外设状态，这是稳定值检查，不证明中断延迟正确。
Timer 另有 `WINDOW` 操作：计数控制在指定数量的时钟内有效，其他操作保持暂停。
`run_cycles` 随输入保存，必须为正；非窗口操作必须为零。
插件独立计算窗口内的计数变化和窗口结束后的状态，不把总线等待当成计数时间。
这是受控暂停检查，尚未检查不停计数时访问寄存器的情况。

可选的脉冲观察器逐时钟检查已声明的单周期输出，累计有效时钟数，拒绝未知值和过宽脉冲。
累计数也是期望/实际输出文件的一部分，复位不清除已经观察到的历史数量。
各外设是否启用窗口、控制极性、哪些端口作为脉冲，由其插件说明，不影响 GPIO 的原有操作格式。
