# 多 IP 扩展检查记录

日期：2026-09-14。环境：Ubuntu 22.04、Vivado 2025.2、Artix-7 xc7a35tcsg324-1。

## 增加了什么

原有 Divider、Multiplier 保持不变，新增七类 IP 的创建、参考模型和自检接口。
`--ip-type` 单独运行某类，`--all` 运行 20 组常用配置；不自动重复种子和时序。
可选扫描矩阵有 5492 组不同 IP 参数，配置和预算检查不需要启动 Vivado。

## 实际检查

没有运行完整大矩阵。新 IP 选了 14 组代表配置，覆盖以下情况：

- 混合符号加减、组合减法、CE 和清零。
- 有控制口的累加、无控制口的无符号溢出。
- 动态方向和步长 3 的计数，以及向下回绕。
- 深度 17 的暂停移位，深度 1 的单比特移位。
- 深度 48 的双地址存储器，以及深度 16 的单口存储器。
- 8 位异或、1 位取反、8 位归约异或和 33 位归约与。

首次运行编号为 `2026-09-14_21-52-45_UTC+0800_49f75f89`。
单口存储器遇到 XCI 零值文本格式差异，修复元数据比较后，在
`2026-09-14_22-02-51_UTC+0800_04f9f225` 中通过。
两批合计，14 组中的 13 组已完成数值自检。

剩下一组是 [累加器 CE/BYPASS 差异](../ip/accumulator/ce_bypass_issue.md)。
问题已缩成两个测试周期，模型没有为了配合实测结果而修改。
它可能涉及文档解释或实现语义，目前不算已确认的 IP bug。

## 不能推出的结论

上述结果不代表 5492 组参数都可创建或都通过。
Catalog 参数探测只用于建立接口和范围，不等于功能测试。
框架故障注入只证明错误能被捕获，也不算真实 IP bug。
本次未验证综合后网表、布局布线或硬件结果。

后续查看某次完整结果时，以 `reports/history/<run_id>/run.json` 和归档证据为准，
不要只凭命令退出或某个 PASS 字样判断整批完成。
