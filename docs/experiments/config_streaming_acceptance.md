# 大矩阵读取检查

2026-09-15。本次只改配置读取、筛选、去重和续跑匹配，不改 IP 参数、数值模型或 Tcl。
用途是降低长期分批测试的内存占用，不把更多参数误算成更多已完成实验。

## 保留的规则

配置逐项读取，但必须扫描完所选入口，才能启动 Vivado。
全局重名、循环引用、嵌套探索和格式错误仍会拒绝；所选 IP/用例的插件参数仍全部校验。
`--limit` 不隐藏后面的错误，续跑跳过完整通过的配置后再计数。
种子、预算、参数或源码变化时，不能把旧结果当作本次已经完成。

小集合用内存去重，超过 8192 个键转入临时 SQLite 索引，比较完整字符串。
没有使用概率过滤器或仅凭短哈希判重。原有列表接口保留，命令行改用迭代接口。
不设 `--limit` 时仍会保留全部待执行配置，因此长测应分批执行。

## 临时索引处理

最初的实现关闭了 SQLite 回滚日志。复核官方说明后，改为内存回滚日志，
保留语句失败时的回滚能力；临时数据库退出即删，不依赖它进行崩溃恢复。
依据见 [SQLite 日志模式说明](https://www.sqlite.org/pragma.html#pragma_journal_mode)。

第一轮完整测试在 `2026-09-15_09-40-53_UTC+0800_c0b50bb3` 中主动中断，返回码 -2。
该记录继续保留，不算测试通过，也不算 IP 异常。
新增测试实际限制 SQLite 可用页面，确认空间不足会抛出错误并删除临时目录。
还检查重复键、含零字节的字符串、长字符串、索引完整性、提前关闭及异常清理。
