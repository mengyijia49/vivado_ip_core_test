# 乘加 IP 自检

`multiply_adder` 对应 `xbip_multadd:3.0`，使用公共创建、testbench 和行为仿真流程。

```bash
python3 scripts/run_all.py --ip-type multiply_adder
python3 scripts/run_all.py --config configs/ip/multiply_adder/extended.json --list-cases
```

## 数值和端口

依据 [PG192](https://docs.amd.com/v/u/en-US/pg192-multadd)，运算是 `C + A*B` 或 `C - A*B`。
不是 `A*B - C`。A、B、C 分别选择有符号或无符号，Python 先解释补码，再做整数运算。
P 输出按 output_high、output_low 截取，不额外舍入或饱和。

输入包括 A、B、C、SUBTRACT；启用流水线后增加 CLK、CE、SCLR。
启用 PCIN 后，以 48 位级联输入代替 C，仍驱动 C 以检查它没有意外影响结果。
输出 P 和 PCOUT 都比较：单 DSP 映射的 PCOUT 为完整 48 位结果，多 DSP 映射为零。
组合模式没有时钟、CE 或清零端口，不能仅凭 IP 名字固定端口表。

## 时序怎么检查

创建阶段通过本机 IP 的参数计算函数获得 A/B、C/PCIN 的延迟，写入
`vectors/ip_timing.json`，与 XCI、输入、期望值一起计算哈希并归档。
它只提供配置元数据，不计算测试数值，也不读取仿真输出。

Python 分别保存乘积、加数和减法控制的历史，模拟 CE 暂停及清零优先级。
单 DSP 完整流水线中，A/B 为 3 拍，C 为 2 拍，PCIN 为 1 拍；减法控制有自己的寄存路径。
宽配置的路径更长，不能把几个输入都统一延迟同样的拍数。
本机内部映射编号 0、1 都是单 DSP，1 表示交换乘法输入；2 才是多 DSP。

定向输入逐个改变 A、B 和加数；检查乘法输入时，另一个输入保持非零。
连续加减序列至少为最长路径延迟的两倍，再在流水线未排空时暂停和清零。
随机测试结束后继续刷新，检查尚未输出的数据。所有有效位严格比较，不使用输出掩码。

## 参数和限制

乘法输入支持 1 至 52 位无符号、2 至 53 位有符号；C 支持 1 至 105 位无符号、
2 至 106 位有符号。支持组合模式和工具的完整流水线模式，以及两种 CE/清零优先级。
PCIN 仅限单 DSP 可用的宽度组合，C 参数固定为 Signed、48 位，避免无效配置重复。

常用回归 10 组，大矩阵 11628 组独立参数。大矩阵只做了配置检查和代表性实测，
不是全部参数都已验证。小位宽穷举只覆盖单周期输入，不覆盖全部流水线历史。
目前验证环境为 Vivado 2026.1、Artix-7；参数计算函数属于本机 IP 安装。
时序判定部分依赖这些参数函数，不能声称它是完全独立于供应商的时序模型。

这里只测试提供的行为仿真模型，不运行综合、实现或网表仿真。
