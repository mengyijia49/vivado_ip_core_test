# AXI GPIO：未启用的第二通道，读回全 1 而不是手册规定的 0

Vivado 2026.1 中，只启用一个 GPIO 通道，再读第二通道的方向寄存器，
实测得到 `0xFFFFFFFF`。手册规定未实现的寄存器应读回 0。

## GPIO 和寄存器是什么

GPIO 就是通用数字输入/输出。输入时可以读取按键或外部信号，
输出时可以控制 LED 或其他数字电路。这里的 0 和 1 表示数字逻辑电平。

一组 GPIO 可以有多根线，这组线叫一个通道。
“单通道、8 位”表示一组 8 根线；“双通道”表示有两组，位宽可以不同。

处理器通过 AXI4-Lite 总线读写 IP 的寄存器。可以把寄存器理解成有地址的
控制或状态格子：写某个格子改变输出、方向，读某个格子查看数值。

| 相对地址 | 寄存器 | 用途 |
| --- | --- | --- |
| `0x00` | `GPIO_DATA` | 第一通道数据 |
| `0x04` | `GPIO_TRI` | 第一通道方向；每位 1 表示输入，0 表示输出 |
| `0x08` | `GPIO2_DATA` | 第二通道数据 |
| `0x0C` | `GPIO2_TRI` | 第二通道方向 |

`0x` 表示十六进制，例如 `0x0C` 是十进制 12。
这些是相对 IP 基地址的偏移，不是 FPGA 引脚编号。

## 为什么认为应该读回 0

[PG144 的寄存器表](https://docs.amd.com/r/en-US/pg144-axi-gpio/Register-Space?contentId=Gz6XpRLZ23QlcvDfJzHV1A)
说明，关闭双通道时，第二通道的数据和方向寄存器不再实现；
读取未实现寄存器应返回全零。

因此，本次期望有手册依据。问题不在“没有第二通道却读到了东西”本身，
而是这个地址返回的值与规定不同。

## 已出现差异的全部配置

独立 VHDL 使用单通道、8 位双向 GPIO，关闭中断，
初始输出数据为 0、方向为 `0xFF`。
“初始方向全 1”表示复位后 8 根线都作为输入。

整批自检另有以下三组配置在同一个地址首先失败：

| 配置 | 第一通道模式 | 位宽 | 中断 | 初始输出数据 | 初始方向 |
| --- | --- | ---: | --- | --- | --- |
| `gpio_bidir1` | 双向，可切换方向 | 1 | 关 | 0 | 1 |
| `gpio_output32` | 固定输出 | 32 | 关 | `0xA5A5A5A5` | 0 |
| `gpio_input32_irq` | 固定输入 | 32 | 开 | 0 | 0 |

“中断开启”表示 IP 另有通知处理器的功能。本次失败发生在寄存器读取，
三组结果说明现象也出现在中断关闭时。

三组第二通道都关闭；配置文件中第二通道仍保留双向、1 位、数据初值 0、
方向初值 1 这些占位参数，但不会因此实际生成第二通道。

## 独立测试具体看到了什么

| 操作 | 期望 | 实测 |
| --- | --- | --- |
| 复位后读第一通道方向 `0x04` | `0x000000FF` | `0x000000FF` |
| 读未启用的第二通道方向 `0x0C` | `0x00000000` | `0xFFFFFFFF` |

AXI 读回数据是 32 位，所以 8 位方向初值会显示为 `0x000000FF`。
`0xFFFFFFFF` 则表示读回的 32 个位全部是 1。

这已构成具体的“手册规定与行为仿真不一致”记录，内部原因和厂商结论尚未确认。
它与[输入方向写数据后切回输出](direction_write_issue.md)是不同的操作和现象。
