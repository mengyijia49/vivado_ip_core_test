# AXI GPIO 自检

使用 `axi_gpio:2.0`，本机验证版本为 Vivado 2026.1。
Python 独立计算寄存器、方向和中断状态，公共 AXI-Lite 后端驱动并检查总线。

```bash
source /data/Xilinx/2026.1/Vivado/settings64.sh
python3 scripts/run_all.py --ip-type axi_gpio
```

常用回归为 12 组配置：3 组单通道，以及双通道输入、输出、双向模式的全部 9 种组合。
它们并非全部通过，已复现的差异见[问题记录](register_issue.md)，不会自动跳过。
本次实际结果见[2026.1 全量运行记录](../../experiments/vivado_2026_full_regression.md)。

## 参数矩阵

`configs/ip/axi_gpio/extended.json` 引用本 IP 的 14 个矩阵文件，共 122304 组不同参数。
没有为了数量重复种子或时序，也没有把其他 IP 的参数放进来。

| 范围 | 组数 |
| --- | ---: |
| 单通道，1 至 32 位，各方向和中断开关，零及低位默认值 | 448 |
| 双通道，两个位宽各为 1 至 32，各方向和中断开关，零默认值 | 18432 |
| 双通道，可用默认数据/方向字段的 0/1 组合，排除全零重复 | 81920 |
| 高位、全一、交替位默认值，分别改变通道 1 或 2 | 21504 |

只列出或选择大矩阵的一部分：

```bash
python3 scripts/run_all.py --config configs/ip/axi_gpio/extended.json --list-cases
python3 scripts/run_all.py --config configs/ip/axi_gpio/extended.json --limit 3
```

关闭通道 2 时其参数固定为规范值；固定输入/输出模式的无效默认参数也固定，
避免把同一电路的无效参数变化计为不同测试。插件和 XCI 检查实际模式、位宽与默认值。

## 检查什么

- DATA、TRI、两个通道、引脚读回、逐位方向和复位恢复。
- 所有 16 种 WSTRB，以及 32 位写数据的行走 1、行走 0 和截断。
- 输入变化、中断状态、写 1 翻转、局部使能、全局使能和软件置位/清除。
- 输入方向下写 DATA 后切回输出，未启用寄存器的读写及对其他寄存器的影响。
- 读写响应、实际握手、回压保持、漏响应、重复响应和未知信号。

策略先选择数值组，再展开成顺序操作；默认每组 256 个数值输入，不是只有 256 次总线访问。
定向操作不依赖随机命中，期间及末尾会复位，完整序列和比较掩码均归档。
数值字段的覆盖比例不等于寄存器状态或操作顺序覆盖率。

## 参考边界

GPIO 忽略 WSTRB，不能按普通 AXI 字节写规则判错。
中断状态为写 1 翻转，不是单纯写 1 清除，见 [PG144 寄存器说明](https://docs.amd.com/r/en-US/pg144-axi-gpio/Register-Space)。
GPIO 字段以配置宽度为限，高位不比较；输入方向下的输出引脚也不作为有效输出比较。
未启用寄存器的读零预期没有屏蔽，定义明确的响应码、TRI 和中断仍严格比较。

输出数据读回依据官方变更记录中修订 14 的功能变更，后端拒绝更早修订。
固定输入/输出的实际方向与 TRI 寄存器初值分开处理，不根据端口是否存在推断寄存器已删除。
中断只检查稳定值，不检查精确延迟；目前没有事务中复位、异步窄脉冲或外部三态电气模型。
固定输入/输出模式下写 TRI 的效果也尚未覆盖，不能把方向端口不存在理解为该寄存器不可访问。
