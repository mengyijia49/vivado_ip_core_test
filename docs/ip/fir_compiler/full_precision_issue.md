# FIR：选了全精度，负数相乘的正结果却变成负数

在 Vivado 2026.1 中，把输入设为 `-128`、系数设为 `[-8,0,0]`，
数学结果应为 `+1024`，仿真实际输出 `-1024`。另一组系数也出现同类现象。
本页先解释这笔计算，再列出全部四组失败配置。

## FIR 是做什么的

FIR 是一种数字滤波器。它不断接收数字，把当前输入和前几次输入分别乘以
一组固定系数，再把乘积相加。音频、通信信号处理经常用到这种计算。

本次有 3 个系数，也叫 3 个抽头。公式为：

```text
当前输出 = c0 × 当前输入 + c1 × 上一次输入 + c2 × 上上次输入
y[n]     = c0 × x[n]     + c1 × x[n-1]   + c2 × x[n-2]
```

`c0、c1、c2` 是创建 IP 时指定的系数；`x` 是测试时送进去的数字；
`y` 是算出的结果。`n` 数的是已接收的输入，不是每一个时钟周期。
IP 可以晚几拍才输出结果，这不会改变这笔计算应有的数值。

例如系数是 `[1,1,2]`，最近三笔输入分别是 3、2、1，
输出就应为 `1×3 + 1×2 + 2×1 = 7`。

## 本次参数是什么意思

| 参数 | 本次设置 | 通俗解释 |
| --- | --- | --- |
| `Data_Width / Data_Sign` | 8 位 / Signed | 输入用 8 个二进制位表示，允许负数，范围是 -128 到 127 |
| `Coefficient_Width / Coefficient_Sign` | 4 位 / Signed | 每个系数用 4 位，范围是 -8 到 7 |
| 小数位 | 输入和系数都是 0 位 | 这里算的都是整数，没有隐含的小数缩放 |
| `CoefficientVector` | 见下表 | 三个乘法各自使用哪个系数 |
| `Single_Rate` | 单速率 | 正常处理时，每接收一个输入，产生一个对应输出 |
| 通道数、路径数 | 都为 1 | 只有一条数据序列 |
| `Full_Precision` | 全精度输出 | 让 IP 自动决定需要保留多少位；测试没有主动要求截短结果 |
| Systolic / Transpose | 两种架构都测 | 内部组织乘法和加法的方式不同，数学公式相同 |

四组还共同启用了输入缓冲、输出 `TREADY`、低电平复位、7 位 `TUSER`
和包尾标记 `TLAST`。这些分别用于排队、允许接收端暂停、清空状态、
携带编号和标记包尾。独立 testbench 同时检查了这些信号，数值差异另行计数。

## 为什么位宽会影响正负号

“8 位有符号”不等于正负各能表示 256 个数。常用的补码表示法，
w 位的范围是 `-2^(w-1)` 到 `2^(w-1)-1`：

| 有符号位宽 | 能表示的范围 | 能否表示这里的正结果 |
| --- | --- | --- |
| 10 位 | -512 到 511 | 装不下 +512 |
| 11 位 | -1024 到 1023 | 装得下 +512，装不下 +1024 |
| 12 位 | -2048 到 2047 | 装得下 +1024 |

所以 **+1024 至少需要 12 位有符号数，+512 至少需要 11 位**。
若不需要表示负数，11 位无符号数就能表示 +1024；本次用的是有符号数，不能混用。

`+1024` 的二进制是 `10000000000`。如果仅用这 11 位并按有符号补码解释，
最左边的 1 会表示负权重，得到的正好是 `-1024`。
`+512` 塞进 10 位时也会出现对应的 `-512`。

生成的 AXI 输出端口虽然是 16 位，但有效计算位宽分别只有 11 位和 10 位。
端口为了按字节传输而补宽，不会补回内部已经丢失的数值范围。

[PG149 的输出位宽说明](https://docs.amd.com/r/en-US/pg149-fir-compiler/Output-Width-and-Bit-Growth)
按实际系数计算全精度位宽增长。本例系数绝对值之和分别是 8 和 4，
生成结果分别增加了 3 位和 2 位。这与记录中的 11 位、10 位一致，
却容纳不了上述最小负输入乘负系数得到的最大正结果。

## 现在能说明什么

独立 VHDL 直接写入固定输入和手算期望值，不从 Python 参考文件读取答案。
它发送输入、等待有效输出，再逐笔比较；同时检查暂停接收时数据保持不变。

正系数 `[1,1,2]` 的 [Systolic 对照](../../../evidence/vivado_2026_1/observations/2026-09-22_12-19-29_UTC+0800_ad024b9b/fir_compiler/positive_systolic_summary.json)
和 [Transpose 对照](../../../evidence/vivado_2026_1/observations/2026-09-22_12-19-53_UTC+0800_08ab159d/fir_compiler/positive_transpose_summary.json)
都通过。这组输出范围为 -512 到 508，10 位有符号数恰好够用，
也解释了为什么正系数对照没有在同一个边界翻转。

目前的具体疑问是：全精度自动位宽计算是否遗漏了有符号负数范围多出的那个端点。
四组观察支持这个方向，但内部原因和厂商认可的处理方式仍待确认。
