# AXI Timer 自检

测试 `axi_timer:2.0` 的行为模型。常用配置 9 组，扩展配置 60 组，
覆盖 8、16、32 位，单/双计数器，以及捕获触发和生成输出的高低有效极性。
单计数器配置保留第二路的默认极性，不把无效参数变化重复计数。

```bash
source /data/Xilinx/2025.2/Vivado/settings64.sh
python3 scripts/run_all.py --ip-type axi_timer
python3 scripts/run_all.py --config configs/ip/axi_timer/extended.json --limit 3
```

## 怎么比较

Python 先生成完整操作序列和期望值，运行时不读取 DUT 结果来修正参考。
总线访问期间拉高 `freeze`，计数窗口内拉低，窗口长度独立记录。
窗口之后等待 64 个时钟，让已经发起的重装载、捕获及中断更新完成，再读寄存器。
测试同时包含连续长窗口和回绕前后的短窗口。

加载寄存器、计数寄存器、保留地址和响应码逐项比较。
控制寄存器只排除手册标明的保留位；没有屏蔽计数值、脉冲计数或中断。
生成输出另逐时钟检查未知值和脉冲宽度，并累计脉冲数，不能只比较窗口结束时的低电平。
AXI-Lite 驱动保留独立地址/数据握手、读写响应回压、响应保持及多发漏发检查。

定向序列检查：

- 复位、全部写字节使能值、加载数据的每个比特、TCR 写入无效和保留地址。
- 上下计数、回绕、单次停止、自动重装载、LOAD 保持、ENT 暂停和 `freeze`。
- 中断状态与中断使能分开检查，写一清除不会被当成普通寄存器写入。
- 捕获覆盖/保持、读 TLR 后重新允许捕获、触发极性，以及禁用捕获和禁用计数。
- ENALL 同时启动两路、镜像读回及清除后保持另一计数器的 ENT。
- 捕获模式的计数回绕仍检查 GENT 输出，但不能据此产生捕获中断。

随机部分变化加载值、控制位、计数窗口长度和 WSTRB；种子、样本与完整操作序列均归档。
预算是数值样本数，不是总线事务数。一个样本会展开多条操作，报告另记实际操作数、
计数时钟数、脉冲和读写次数；输入参数覆盖率不等于寄存器状态覆盖率。

## 依据和限制

自动重装载的连续周期含一个额外时钟，与
[PG079 的周期公式](https://docs.amd.com/r/en-US/pg079-axi-timer/Generate-Mode)一致。
窗口结束时已经请求的重装载仍会完成；该暂停边界用独立 VHDL 核对，
见[接口及时序探测](interface_probe.md)。
输出脉冲和模式相关中断是两条规则，不能混为一谈，见
[端口说明](https://docs.amd.com/r/en-US/pg079-axi-timer/Port-Descriptions)。
捕获保持按编程章节的“读 TLR 后重新捕获”处理，见
[捕获流程](https://docs.amd.com/r/en-US/pg079-axi-timer/Capture-Mode)。

当前未接入 PWM、64 位级联、不停计数时的总线访问、在途事务复位及异步捕获的亚周期相位。
捕获触发在暂停后的稳定计数值上执行，不声称检查了精确的外部事件时间戳延迟。
不仿真综合后网表或板级时序。60 组参数不代表 60 组均已运行，真实运行记录另行保存。
