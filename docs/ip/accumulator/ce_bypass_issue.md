# 累加器：要求暂停后，输出仍跟着旁路输入改变

Vivado 2026.1 的 `acc_signed_control` 配置中，测试先得到输出 1，
随后关掉时钟使能、保持旁路开启并输入 0。参考模型认为应保留 1，实际输出变成 0。
疑问在两个控制信号同时出现时的优先顺序。

## 累加器做什么

累加器会记住上一次结果，再把新输入加进去：

```text
新结果 = 旧结果 + 本次输入
```

例如初始为 0，依次输入 2、3、4，结果依次为 2、5、9。
本次还支持减法，运行时可以改成 `新结果 = 旧结果 - 本次输入`。
“上一拍、下一拍”指相邻的时钟处理时刻。

## 本次配置里的参数

| 参数 | 值 | 含义 |
| --- | --- | --- |
| `input_width / input_type` | 8 / Signed | 输入是 -128 到 127 的整数 |
| `output_width` | 16 | 结果用 16 位保存，有符号范围为 -32768 到 32767 |
| `operation` | `Add_Subtract` | 运行时选择加法或减法 |
| `clock_enable` | true | 带 CE 端口，用于允许或暂停状态更新 |
| `bypass` | true | 带 BYPASS 端口，允许直接装入本次输入 |
| `sync_clear` | true | 带同步清零，在时钟处理时刻清除结果 |
| `ce_overrides_reset` | false | 清零与 CE 同时作用时，清零不受 CE 阻止；这项并没有单独回答 BYPASS 的优先级 |

BYPASS 的作用是跳过加减，把输入直接装进输出。
例如旧结果为 9、输入为 2：普通加法得 11，旁路则得 2。
[PG119](https://docs.amd.com/v/u/en-US/pg119-c-accum)给出了这些端口的含义。

## 实际送入的两拍

测试中的 `B` 是输入数字，`Q` 是输出结果；本段没有主动清零。

| 顺序 | CE | BYPASS | 输入 B | 参考 Q | 实际 Q |
| --- | ---: | ---: | ---: | ---: | ---: |
| 前一拍 | 1 | 1 | 1 | 1 | 1 |
| 下一拍 | 0 | 1 | 0 | 1 | 0 |

第一拍让输出处于已知的 1。第二拍同时要求“暂停更新”和“旁路装入 0”：
参考模型让暂停优先，因此保持 1；实测表现为旁路生效，输出成了 0。

这不是加法溢出，0 和 1 都远在输入输出可表示的范围内。
目前只确认这一组参数下存在控制语义差异。
需要厂商或明确的时序说明回答 CE 是否应挡住旁路操作，才能决定改 IP 还是改参考模型。
