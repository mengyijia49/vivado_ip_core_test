# AXI-to-APB Bridge 自检

## 已检查内容

当前只测 APB4 模式。Python 参考模型为每个 APB 从设备分别保存 32 位数据，
根据 AXI 地址选择从设备，再按 `WSTRB` 更新对应字节。指定的错误地址返回
APB `PSLVERR`，预期 AXI 侧得到 `SLVERR`，且原数据不变。

testbench 还会直接观察 APB 总线：

- 一次只允许选中一个从设备，地址必须落在对应窗口。
- 传输必须先进入 setup，再进入 access。
- `PREADY` 拉低时，地址、数据、写使能、`PSTRB`、`PPROT` 和 `PSEL` 不能变。
- `AWPROT` 或 `ARPROT` 必须原样传到 `PPROT`，`WSTRB` 必须原样传到 `PSTRB`。
- 只有 `PSEL`/`PENABLE`/`PREADY` 同时有效时，读写才能完成。

常用回归有 4 组配置，覆盖 1、2、4、8 个从设备、0 至 3 拍等待、
零地址和非零基地址，以及有无错误注入。大矩阵有 210 组配置，另外包含
16 个从设备、32 位地址和 4 拍等待。

## 当前限制

- 还没有测 APB3。APB3 没有 `PSTRB` 和 `PPROT`，需要单独的端口和参考规则。
- 当前地址窗口都是连续的 4 KiB，未测不同大小或中间留空的窗口。
- 行为仿真实际运行了四组代表配置，不代表 210 组大矩阵都已运行。
- 本次没有发现 AXI-to-APB Bridge 的功能异常。
