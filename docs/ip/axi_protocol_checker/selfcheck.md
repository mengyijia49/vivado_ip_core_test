# AXI Protocol Checker 自检范围

当前接入 AXI4 读写模式。testbench 把同一组 AXI 信号接到检查器，先发送一组合法读写事务，确认不应报错；再逐项注入协议错误，核对 `pc_status` 中对应的一位以及 `pc_asserted`。

已检查的错误包括：保留的 AWBURST/ARBURST 值、非法 WRAP 长度、超过总线宽度的 AWSIZE/ARSIZE、VALID 在 READY 前撤销，以及地址在等待握手时改变。每项测试前都会复位检查器，避免上一次锁存的错误影响下一项。

1024 位数据总线已经达到 `AxSIZE` 三位编码的上限，不能构造“尺寸更宽”的值。因此该宽度改为检查超过 16 拍的 FIXED burst，写地址和读地址各测一次。

参考结果不是从 DUT 输出反推。Python 按公开规则和场景生成预期的 160 位状态值。
仿真同时保存输入场景、预期状态和实际状态。

参数覆盖 32 至 1024 位数据、32/40/64 位地址、1 至 32 位 ID、多种最大 burst 长度、最大未完成事务数、窄传输支持和错误响应检查。

当前固定从设备一侧检查主设备发出的请求。没有接入主设备一侧的响应违规、AXI3、AXI4-Lite、只读、只写、轻量检查模式、USER 字段、超时建议项和控制寄存器。行为仿真只能说明所列场景的状态输出，不能代替对全部 AXI 规则的证明。
