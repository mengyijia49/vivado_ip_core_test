# 浮点乘法：两个接近 1 的数相乘，输出却接近 0.5

Vivado 2026.1 的双精度低延迟乘法配置，在一组固定输入中有五笔结果不符。
其中一笔应舍入为 1.0，实际约为 0.5。换成速度优化架构后，同一组输入通过。

## 这个 IP 算什么

这次使用 Floating-Point IP 的乘法功能，计算 `结果 = A × B`。

浮点数可以表示很小或很大的小数，类似科学计数法。
但它可保存的有效数字有限，算出的精确值有时需要舍入到最近的可表示值。
因此测试要比较“按格式正确舍入后的结果”，不能要求无限精度。

本例选双精度，总共 64 位：

| 部分 | 位数 | 用途 |
| --- | ---: | --- |
| 符号 | 1 | 正数还是负数 |
| 指数 | 11 | 控制数值量级 |
| 显式小数部分 | 52 | 保存有效数字的细节 |

参数里的 `input_fraction=53` 包括正常数隐含的最高有效位。
所以“有效数字 53 位”和“实际存了 52 个小数位”不矛盾。

## 出错的一笔怎么算

这笔输入的十六进制编码为：

| 输入 | 编码 | 它表示的数 |
| --- | --- | --- |
| A | `3FEFFFFFFFFFFFFE` | `1 - 2^(-52)`，比 1 小一点 |
| B | `3FF0000000000001` | `1 + 2^(-52)`，比 1 大一点 |

这里的十六进制只是方便完整记录 64 位数据，不是把它当普通整数相乘。
令 `ε = 2^(-52)`，可以像初中乘法公式一样展开：

```text
A × B = (1 - ε) × (1 + ε)
      = 1 - ε²
      = 1 - 2^(-104)
```

精确结果比 1 小极其微小的一点，正确舍入到双精度应为 1.0。
但这笔输出为 `3FE0000000020000`，约 0.500000000015。
这个差距远大于最后一位舍入造成的误差。

## 哪些参数下出现了问题

两组失败都使用乘法、双精度、`Low_Latency`、`Performance`、
`Max_Usage`，并启用下溢、上溢和无效运算标志。

| 参数 | 含义 |
| --- | --- |
| `Low_Latency` | 选择偏向较短处理延迟的乘法架构 |
| `Performance` | 选择性能优化目标 |
| `Max_Usage` | 选择较多使用器件内专用 DSP 运算资源的实现 |
| `TUSER` 输入标签 | 跟随输入的数据编号等附加信息，不参与乘法 |
| `TLAST` | 标记一组数据的最后一笔，不参与乘法 |
| 异常标志 | 告诉使用者是否出现数值过大、过小或无效运算 |

| 失败配置 | A / B 输入标签位宽 | A / B 包尾标记 | 观察结果 |
| --- | --- | --- | --- |
| 自动化 `fp_mul64_low` | 7 / 9 位 | 都启用，两者同时为 1 才给输出包尾 | 数值自检失败 |
| 独立固定输入 VHDL | 都为 0，即关闭 | 都关闭 | 16 笔中有 5 笔数值不符 |

独立复现虽然关闭了输入标签，输出仍用 3 位 `TUSER` 携带异常标志。
不能把“没有输入标签”理解成完全没有输出 `TUSER` 端口。

## 五笔失败都是什么

序号从 0 开始，所有编码都是 64 位浮点位型。五笔的异常标志实际都为 0。

| 序号 | 输入 A | 输入 B | 应有输出 | 实测输出 |
| --- | --- | --- | --- | --- |
| 0 | `3FEFFFFFFFFFFFFE` | `3C80000000000001` | `3C80000000000000` | `3C70000000020000` |
| 1 | `3FEFFFFFFFFFFFFE` | `3FF0000000000001` | `3FF0000000000000` | `3FE0000000020000` |
| 8 | `BFEFFFFFFFFFFFFE` | `3FF0000000000001` | `BFF0000000000000` | `BFE0000000020000` |
| 9 | `3FEFFFFFFFFFFFFE` | `BFF0000000000001` | `BFF0000000000000` | `BFE0000000020000` |
| 10 | `BFEFFFFFFFFFFFFE` | `BFF0000000000001` | `3FF0000000000000` | `3FE0000000020000` |

序号 8、9 是一正一负，应该约为 -1；序号 10 是两个负数，应该约为 +1。
这些样例帮助检查问题是否也影响负数，但五笔失败本身不等于五个独立 bug。

## 测试是怎么检查的

[独立 VHDL](../../../tests/fixtures/ip/floating_point/arithmetic/multiply_rounding_probe.vhd)
直接保存了输入编码和期望编码。A、B 两路分别等待对方准备好，
都接收成功后才发送下一对输入；输出按收到的先后顺序比较。
它还检查输出不能早于输入被接收，避免把错配的两笔数误当成数值错误。

| 对照配置 | 同一组 16 笔输入的结果 |
| --- | --- |
| `Speed_Optimized + Max_Usage` | 通过 |
| `Speed_Optimized + No_Usage`，不使用 DSP 的选项 | 通过 |

已有证据把疑问集中到低延迟实现，但还没有确定内部是哪一步造成差异。
