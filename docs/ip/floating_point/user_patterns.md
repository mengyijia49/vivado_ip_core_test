# USER 标签覆盖修正

定向输入检查曾发现，旧写法先按通道左移，再截到 USER 位宽。
B 的位宽不超过 7、OPERATION 的位宽不超过 14 时，定向前缀中的标签一直为零。
策略生成的后续输入不一定如此，但不能靠它弥补定向边界与标签组合的缺口。
这是框架的输入覆盖问题，不计为 IP bug。

比较、加减、乘法和除法现在共用 `walking_bits_and_full_width_tags:1.0`：
交替使用全零、全一、逐位置一、逐位清零和覆盖整个位宽的确定性标签。
各路分别生成，最高支持 256 位，窄位宽也会变化。
报告的 `reference_contract.user_pattern` 记录这个版本，历史输入文件不改写。

这次修改只针对定向前缀的 USER。数值、操作码、TLAST、事务顺序、
输入间隔和输出回压不应改变；期望输出的 USER 按新输入重新拼接，异常位仍单独检查。
对比历史结果时不能再要求整份输入文件逐字相同，也不能忽略新 USER 的实际输出。

单元测试检查 1、2、3、5、31、32、129、256 位的模式，
并检查可编程比较的窄 B、OPERATION 通道能取到全部标签值。
2026.1 的实际结果见[全量运行记录](../../experiments/vivado_2026_full_regression.md)。
